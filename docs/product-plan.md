# 서비스 설계 초안

## 컨셉

취준생·직장인 등 학생 신분이 아닌 사람도 자신이 원하는 활동을 등록하고 자기 시간표를 만든다. 대학 수강신청과 시간표의 익숙한 형식을 가져오되, 활동·목표·시간은 사용자가 자유롭게 설정한다. 시간표 + 투두 + 간단 일지를 연결해 자기주도 학습과 시간 관리 훈련을 돕는다. 공부 루프는 임시 이름이다.

## 최초 시작 — 나만의 수강신청

1. 무엇을 할지 활동 이름을 자유롭게 입력한다. 예: 코딩테스트, 영어, 자격증, 독서. 예시는 선택을 돕는 용도이며 고정 과목 목록이 아니다.
2. 각 활동의 목표와 선택적 카테고리·색상을 설정한다. 목표와 성공 기준은 사용자가 직접 정한다.
3. 원하는 요일·시각·길이로 활동을 배치한다. 시간을 아직 정하지 않은 활동은 미배치 목록에 둔다.
4. 시간표 만들기를 마치고 메인 화면으로 들어간다. 처음부터 빈 시간표로 시작하는 것도 허용한다.

최초 설정 완료 여부를 공간별로 서버에 저장하여 새로고침이나 재접속 때 자동으로 다시 시작하지 않는다. 이후 활동 추가·수정·삭제와 시간 변경은 시간표 화면에서 진행한다. 설정 재실행은 사용자가 선택하는 기능이며 기존 내용을 초기화하지 않는다.

## 카테고리와 사용자화

카테고리는 선택 사항이다. 학습·커리어·건강·개인 활동 같은 시작 예시를 제공하되 직접 추가·이름 수정·색상 변경할 수 있다. 활동 이름과 카테고리를 분리한다. 같은 카테고리에 여러 활동이 속할 수 있고 카테고리 없이도 활동을 만들 수 있다. 자동 추천이나 랜덤 시간 배분보다 직접 선택하고 조정하는 경험을 우선한다.

## 시간표·할 일·일지의 역할

- 활동: 지속적으로 하고 싶은 것. 예: 영어 공부.
- 시간표 블록: 활동에 확보한 시간. 예: 화·목 20:00~21:00.
- 할 일: 구체적으로 끝낼 행동. 예: 단어 30개 복습. 시간표에 배치하지 않아도 등록 가능.
- 실행 기록·일지: 실제 수행 시각과 소요 시간, 짧은 메모·막힌 이유. 계획한 시간과 분리해 보존.
- 주간 계획·회고: 기간별 목표와 성공 기준, 예상과 실제 비교, 다음 주 개선점.

시간표 블록이 끝났다는 이유만으로 할 일을 자동 완료하지 않는다. 사용자가 실제 수행 여부와 기록을 확인한다.

## 화면 방향

메인은 요일 열과 시간 행이 있는 주간 시간표다. 색상 있는 활동 블록을 표시하고 선택하면 연결된 할 일과 실행 기록·일지를 연다. 미배치 활동/할 일 목록과 주간 회고를 함께 접근할 수 있게 한다. 달력 월간 보기는 기록 탐색용 확장 후보다. 활동 추가·시간 변경은 폼으로도 가능하게 하고 드래그 편집은 선택 기능으로 둔다.

## T06 범위

공개해도 괜찮은 본인의 실제 계획 1개, 할 일 5개, 실행 기록 3개 이상을 사용한다. 로그인 없이 접근 가능한 화면에 공개 안내를 표시한다. 장기 서비스의 사용자별 로그인·개인 기록은 이후 범위다.

1. 계획: 기간·우선순위·성공 기준·예상 시간, 이전 내용이 보존되는 수정 이력.
2. 할 일: 생성·수정·완료·완료 취소·삭제, 마감일·과목 태그·예상 시간, 검색·필터·정렬.
3. 실행: 시작·종료·실제 소요 시간·막힌 이유·메모. 예상 시간을 덮어쓰지 않는다.
4. 회고: 완료·지연·막힘·시간 차이 집계, 숫자를 눌러 근거 기록으로 이동, 개선 문장을 다음 계획으로 전달.
5. 보관: 서버 DB 저장·새로고침 유지·전체 JSON 내보내기.

## 캘린더 설계

주간 시간표는 독립된 활동과 반복 시간표 블록에서 만든다. 요일·시작/종료 시각·유효 기간을 규칙으로 저장하고 수년치 날짜별 데이터를 미리 만들지 않는다. 실제 실행 기록은 발생한 날짜별로 저장한다. 특정 날짜만 변경하거나 취소하는 기능은 이후 예외 구조로 확장할 수 있다. 타이머는 매초 DB에 기록하지 않는다. 조회는 화면에 표시하는 주·월 범위로 제한한다.

## 구현된 DB 구조

실행 대상은 db/002_app.sql이다. 공간·문서 엔티티·중복 요청 처리 표로 저장하며 활동, 사용자 정의 카테고리, 반복 시간표, 계획, 할 일, 실행 기록, 회고와 계획 이력을 JSONB 엔티티로 보관한다. lib/model.ts에서 필드와 참조를 검증하고 공간 버전 잠금으로 변경 충돌을 막는다. 기존 db/001_initial.sql은 미적용 이전 초안이며 실행하지 않는다. 반복 시간표의 예정 시간을 실행 기록으로 세지 않는다. 실제 Neon은 연결 값 입력 후 검증해야 한다.

현재 API는 공간 전체를 조회·전송하므로 공개 과제 MVP에 적합한 단계다. 장기 다중 사용자 운영 전에 인증·개인 공간 접근 제어·부분 업데이트·페이지 조회를 추가하고 엔티티별 테이블/인덱스 최적화를 검토한다. 변경된 엔티티만 DB에 쓰며, 전체 문서를 변경 때마다 다시 쓰지 않는다.

## 다중 사용자로 확장할 준비

계획은 workspace_id에 속하고 모든 하위 데이터는 계획을 통해 같은 공간에 속한다. T06의 공개 공간과 향후 개인 공간을 분리할 기반이다. workspace_id 자체는 접근 권한이 아니며, 로그인과 서버 권한 검증을 구현하기 전에는 개인 기록을 수집하지 않는다. 공개 DB 연결 문자열을 브라우저로 전달하지 않는다.

## 구현 순서

1. 최초 활동 등록 → 시간표 생성 흐름과 활동·반복 시간표 DB 구조 반영.
2. Next.js 앱과 서버 DB 연결, 마이그레이션 실행.
3. 계획·할 일 편집과 이력 보존.
4. 실행 기록 및 완료 중복 방지.
5. 회고 집계·근거 연결·다음 계획 전달.
6. 캘린더 표현, 공개 안내, 데이터 내보내기.
7. 시크릿 창 접근·저장 유지·입력 안전성·비밀값 점검·배포 및 제출 문서.

## 검증해야 할 핵심

- 완료 요청은 동일 작업을 구분하는 request_key를 재사용하고 DB 고유 제약으로 한 번만 처리한다.
- 완료 취소 후 다시 완료는 새 요청으로 처리한다. 완료 집계는 현재 상태를 기준으로 계산한다.
- 계획 변경과 revision 삽입은 한 트랜잭션에서 처리한다.
- 집계와 근거 목록은 같은 필터를 사용한다.
- 정렬 동률은 생성 시각과 ID로 고정한다.
- SQL 파일은 아직 실행되지 않았으며 실제 DB에서 검증 후 최종 스키마 계약을 갱신한다.
